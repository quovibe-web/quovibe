# v1.7.0

## Features

### Stock Splits

Retroactive stock-split handling, mirroring Portfolio Performance's three-page
wizard: ratio → transaction preview → quote preview.

- New **`/p/:pid/securities/:id/split`** wizard. The ratio is collected as two
  labelled fields (Old shares → New shares) plus a live direction sentence,
  rather than a single free-text `a:b` box — a single box silently inverts a
  reverse split for anyone who types it the way their broker states it.
- Preview pages show exactly which transactions and which historical quotes
  will be restated before anything is written.
- **Security Events** section on Security Detail lists applied splits. Its row
  action re-opens the wizard pre-filled with the inverted ratio, which is how
  a split is undone — the undo leaves its own marker rather than deleting the
  first, matching upstream behaviour.
- Applied destructively at write time: `xact.shares` and
  `price.{value,open,high,low}` are rewritten for rows strictly before the
  ex-date. Rows *on* the ex-date are untouched. `volume` is never rescaled (it
  is a share count, not a price), and `xact.amount`, `fees`, `taxes` and every
  `xact_unit` row are left alone — so implied per-share price and every FX
  decomposition stay consistent.
- `latest_price` is re-synced when quotes were rewritten. This is a deliberate
  divergence from upstream, which leaves the latest quote alone: for a recent
  split every historical bar predates the ex-date, so without the resync the
  adjusted history disagrees with the untouched latest quote and the displayed
  position value stays wrong.
- Rounding is half-even on the raw scaled integer, after a division carried at
  10 significant digits — a single shared implementation, never re-derived.

See ADR-019 for the write-time-vs-compute-time rationale.

## Fixes

### PP-XML import: user-defined exchange rates were ignored

Reported via GitHub against a HUF-base portfolio carrying its own HUF/AED,
HUF/CHF, HUF/USD and HUF/EUR rate series. Import reported success while every
cross-currency figure came out wrong, with the server logging
`dropping 178 securities from rollup due to missing FX rates`.

- **User-defined exchange-rate series are now ingested.** In PP such a rate is
  stored as a *security* carrying a `targetCurrency`, whose price series is the
  rate history. Both columns were already imported, but nothing ever read them,
  so the series sat inert in the database. For pairs the ECB does not publish
  at all (AED, RSD, HRK) that series is the only possible source — which is why
  these files worked in PP and not here. `applyBootstrap` now copies them into
  the rate cache.
- **The cross-currency backfill no longer runs against an empty cache.** It
  executes inside `applyBootstrap`, which on a fresh import always completes
  before the connection pool's open hook arms the FX scheduler — so it was
  guaranteed to find no rates, and would not retry until a process restart. It
  now also re-runs after every successful rate fetch.
- **The rate auto-fetch no longer overwrites user-supplied rates.** Its guard
  covered only manually-entered rows, so an imported or uploaded series would
  have been replaced by ECB reference rates seconds after import. Precedence is
  now: manual entry > imported/uploaded series > automatic fetch.
- **Rate fetch failures are now reported per pair.** The scheduler discarded
  the per-pair outcome, which made "no upstream publishes this pair" and
  "this host cannot reach the rate provider" indistinguishable — both only
  surfaced much later, and far from their cause, as a missing-rate warning.
  Eager and scheduled refreshes are now distinguishable in the log.

> **Known limitation.** The direction of an ingested series follows PP's
> `XXX/YYY` quote notation (the price is target-currency units per one
> base-currency unit). This has not yet been confirmed against a real
> PP file carrying such a series. If a portfolio's converted values look
> inverted after upgrading, please report it with the affected currency pair.

> **Cosmetic.** An exchange-rate series is a security as far as the database is
> concerned, so it appears in the securities list as a zero-holding row.
> Filtering those out is a separate change.

### Other

- Split preview normalizes the stored transaction type, so preview counts match
  what the apply step actually rewrites.
- Split wizard: state is kept when navigating Back, preview columns are sized
  to the wizard card, the step indicator wraps on narrow viewports, and preview
  warnings render correctly in discrete mode.

## Notes

No schema changes. `bootstrap.sql` §1+§2 parity with the vendor importer is
untouched — `security.targetCurrency` and the rate-source column both already
existed.
